1. Rebooked deals - BOX holds the pre-rebook contract version (45 of the 156 complete deals)
For deals amended / rebooked in GBO (mostly May 2025), BOX holds the original version:
- notional / principal = the pre-rebook amount (e.g. x1.1544118 on 10 deals of book 3684.44);
- flows paid before the rebook, cancelled in GBO, arrive in BOX as Live and are counted as cash: INTERESTCASH sums all
  paid flows with no cancel check (datadeal load, L150-153);
- trade / capture date = the original trade; GBO shows the rebook date.
Example: GBO 14550803.44 = BOX 38057225.513 (INTERESTCASH: GBO 0, BOX the sum of the cancelled paid flows).

2. Current interest on compounded overnight legs (SOFR, CDI, TIIE) - 74 deals
BOX takes INTERESTCUR from the current flow's amount (p_update_current_values), which is 0 until a compounded period
ends. GBO shows a projection of the current period's coupon: within about 0.1% of the period's scheduled cash flow
in GBO (e.g. GBO INTERESTCUR 452,513 vs scheduled 452,872).
Example: GBO 13658753.44 / BOX 11845822.513: GBO 90,917,555.19, BOX 0.
Questions:

Confirmed / explained - no action
- P&L accrual and fee accruals (PLACC): not calculated in BOX, as you said.
- RATECUR / INTERESTCUR: BOX's stored values equal your rule on every leg checked (max RATE / sum AMOUNT of the
  current interest flow). On USD legs GBO leaves RATECUR at 0 while BOX stores the coupon rate - a GBO convention.
- Maturity date: BOX takes RAW MATURITYDATEREAL = the last flow's payment date; GBO keeps the accrual end date
  (1-5 days apart on overnight compounded legs). Just confirm this is the date you want BOX to keep.
- FK_FLOATINGRATE (GBO 0 = fixed leg) and code values (instrument, status, portfolio property, fee type) map
  one-to-one.
